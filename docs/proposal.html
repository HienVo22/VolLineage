VolLineage: Historical Tennessee Football Roster Archive & Roster Transition Analysis

COSC 445 Digital Archaeology, University of Tennessee, Knoxville — Final Project Deliverable 3: Project Proposal
Team: Hien Vo, Hamzah, Bansari — October 2026 — Repository: github.com/HienVo22/VolLineage

1. Objective

How has the composition of the Tennessee football roster changed from 1998 to the present, and how reliably can a single athlete be followed through an archival record that never assigned stable identifiers? The project will (1) recover every surviving season roster for Tennessee football from web archives, (2) resolve each listed athlete to one durable player identity despite changing jersey numbers, positions, class designations, redshirt labels, and name spellings, (3) store the result in a normalized SQLite database with provenance on every row, and (4) use that database to quantify roster transitions: year-over-year retention, redshirt and position-change rates, jersey-number reuse, and transfer-portal arrivals and departures, benchmarked against the rest of the FBS.

2. Motivation

UTSports roster pages were built for one season and then overwritten. Since 1998 the athletics site has moved through at least four platforms (hand-built HTML, the CollegeSports/CSTV host, the CBS-era m-footbl pages, and the current Sidearm site), and each changed the URL scheme and the table markup. The official site has no historical roster archive; the past exists only as Internet Archive snapshots. That makes this a textbook digital archaeology problem: the artifacts are fragmented across hosts, the context (which season a page describes) is sometimes recoverable only from a URL fragment or a capture timestamp, and the same person appears under several labels.

The recovered data also answers questions that fans and reporters currently argue about without evidence. Did the transfer portal change how much of the roster turns over each year, or was churn always high? Which position groups switch most often? How quickly are jersey numbers recycled? Tennessee is a good case study because the window covers the full Fulmer, Kiffin, Dooley, Jones, Pruitt, and Heupel sequence, so coaching regime changes should be visible in roster churn.

Primary source: Wayback Machine captures of UTSports football pages. We used the Internet Archive CDX API to measure what survives before committing to the plan. Counting only unique, status-200 captures (collapsed by content digest), four URL eras are already enumerated:

The 1998–2003 host still has to be located and is expected to be thinner. Roster index pages number in the low thousands; most captures are individual player bio pages (more than 7,000 in the 2011–2017 era alone), which carry hometown, high school, height, and weight, the fields that make entity resolution possible. Retrieval: enumerate with the CDX API, fetch each capture through the id_ raw endpoint with rate limiting, cache raw HTML and capture metadata under data/raw/, and parse with BeautifulSoup. Playwright is reserved for any Sidearm-era page that requires JavaScript rendering.

Breadth source: CollegeFootballData.com API (free key). Season rosters for every FBS team, roughly 130 teams × 110–125 players, or about 15,000 rows per season and roughly 300,000 roster rows for 2004–2025, plus transfer-portal entries for 2021 onward. This lets us compare Tennessee's churn with SEC and FBS baselines instead of reporting it in isolation.

Cross-check source: Sports-Reference College Football season rosters, used for spot validation where Wayback coverage is thin. Accessed sparingly within their published rate limits, not bulk-scraped.

Estimated volume. About 50,000 page snapshots retrieved and parsed; roughly 3,500 Tennessee roster rows (28 seasons × 110–125 players); about 300,000 FBS roster rows from the API; several thousand portal records; several thousand derived career events; and tens of thousands of candidate alias strings produced during matching.

Expected challenges. (a) Markup drift across four platforms requires one extractor per era that emits a shared record format. (b) Duplicate and near-duplicate captures must be collapsed to one canonical capture per season. (c) Season attribution: a page captured in January 2015 may describe the 2014 roster, so the season must be inferred from page text, URL, and the football calendar rather than from the timestamp alone. (d) Identity drift: spellings, suffixes, nicknames, number changes, and redshirt labels all vary independently. (e) Older pages omit height, weight, or hometown. (f) The API and the school pages disagree on positions and class year, so integration needs reconciliation rules that preserve both values rather than overwriting one. (g) Politeness and runtime: roughly 50,000 Wayback requests at one to two per second is 7–14 hours of fetching, so the fetcher must be resumable and run in batches.

4. Approach

The pipeline is Ingestion → Entity Resolution → Relational SQLite → Analysis, implemented in Python 3.11 with requests, beautifulsoup4, pandas, sqlite3/sqlite-utils, and pytest. The repository skeleton and initial schema are already in place.

  • Discovery and retrieval. Per-era CDX enumeration scripts; a resumable, rate-limited fetcher; raw HTML plus capture metadata kept permanently so any parsed row can be traced to its artifact.
  • Extraction and context recovery. Era-specific parsers emitting a common record: raw name, jersey, position, class, height, weight, hometown, high school, inferred season, source URL, and snapshot timestamp. Unit tests run against saved HTML fixtures from each era.
  • Entity resolution. Normalize names (case, punctuation, suffixes); block candidates on last name plus hometown or high school; score with name similarity, career-overlap plausibility (a career spans at most about six seasons), and physical-attribute consistency. Output players and player_aliases with a confidence score; low-confidence matches go to a manual review queue. A hand-labeled gold set of about 200 player pairs will measure matcher precision and recall.
  • Storage. SQLite schema with players, seasons, roster_entries, player_aliases, and career_events. Identity, season appearance, alias evidence, and derived transitions are separate tables so a correction never destroys a source row.
  • Analysis. Season coverage report; retention curves by coaching regime; position-change and jersey-reuse rates; portal inflow and outflow against SEC and FBS baselines from the API. Delivered as SQL, pandas notebooks, and static charts. A small Next.js/Tailwind viewer of individual player lineages is a stretch goal.

Course connection: web archive discovery and retrieval, scraping fragmented HTML, provenance-preserving storage design, cleaning and entity resolution, context recovery, and analysis of the recovered record.

7. Expected Outcome

A reproducible SQLite archive of Tennessee football rosters from 1998 to the present, with provenance for every row and a resolved player identity table; a measured entity-resolution quality report; and an analysis that answers how roster turnover, position switching, jersey reuse, and portal movement have changed across coaching eras, placed against FBS baselines. The result can be evaluated on three numbers: percentage of seasons with a recovered roster, matcher precision and recall on the gold set, and agreement rate with Sports-Reference spot checks. The code, schema, and processed extracts will be public in the project repository; raw HTML captures stay local and are not redistributed.
